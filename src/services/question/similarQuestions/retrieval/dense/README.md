# Dense Retrieval

This directory contains the production Dense v1 implementation.

The public entrypoint is `../../similarQuestionsSearch.service.ts`.

## Runtime

The application reads current eligible question versions from MongoDB.

It builds a process-local HNSW index for each embedding model, queries an oversampled candidate set, scores those candidates with the application-owned cosine implementation, validates them again, and returns ranked candidates.

The index is lazily built and refreshed after five minutes at most; evaluation corpora may use the exact streaming fallback.

No optional Python package or worker is required.

Document embeddings are generated by the question embedding worker and stored before retrieval can use them.

The configured embedding provider and model are controlled by the existing embedding configuration.

HNSW is used only for candidate generation. The application still owns exact scoring, thresholding, current-version validation, self-filtering, and final ranking.

Retrieval evaluation uses HNSW by default. Set `RETRIEVAL_EVAL_USE_HNSW=false` to run the exact streaming baseline, then compare both reports on the same dataset and embeddings.
